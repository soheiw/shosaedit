## 最新の実装 実測電流と推定負荷

### 実装したもの

| ファイル | 役割 |
| --- | --- |
| `measured-load.js` | 符号付き電流、トルク概算、負荷率、鮮度判定の純粋計算 |
| `measured-load-panel.js` / `.css` | 全17軸の表、係数・許容値設定、ピーク、超過継続時間、記録と JSON 保存 |
| `telemetry.py` | ローカル／共有 JSON の読み取り、検証、タイムアウト、元計測時刻の保持 |
| `launch.py` | `GET /api/telemetry/status` と `POST /api/telemetry/configure` |

| `docs/current-telemetry.md` | 接続方法と JSON 契約 |
| `tests/test-measured-load.mjs` / `tests/test_telemetry.py` | 数値・未取得・古い値・API・ファイル取り込みの検査 |

パネルは CAD 起動とは独立して初期化します。電流 A、推定 N·m、許容値に対する絶対値の割合、温度、電圧を表示します。係数と許容値はブラウザの localStorage、取得元パスは `.motion-sync/telemetry-config.json` に保存します。履歴はブラウザ内にあり、利用者が JSON 保存する必要があります。記録には換算設定と元計測時刻を含めます。

初期係数はメーカー仕様表の停止トルク÷停止電流による未校正の概算です。精密な電流―出力軸トルク特性や摩擦モデルではありません。許容トルクは空欄で開始し、ストール値を自動で安全限界にしません。未知型番の第5関節・指の係数も空欄です。型番と実機 ID の対応は別途実機照合が必要です。

現行の取得間隔は概ね0.5秒です。表示するピークは受信サンプル中のピークであり、それより短い突発負荷を取り逃す可能性があります。高速負荷解析が必要なら、TD 側の取得周期で時系列をバッファ／記録し、間引き前のピークを保持する機能を追加してください。これは未実装です。

### 取得経路と残作業

予定経路は `既存TDモニターのPresent Current → キャッシュ → 共有JSON → ShosaEdit API → パネル`。ヘルパー単独では TD に接続されません。現在のキャッシュ構造を確認して組み込む作業が残っています。別のシリアル読み取りプロセスを追加して TD とポートを競合させないこと。

接続後の手順：

1. 実際のモデル番号、ID 対応、電流レジスタ単位を取得・照合する。
2. 既存監視処理が成功した読み取りから、Present Current と取得時刻を取り出す。Goal Current、PWM、Present Load を実測電流に代用しない。
3. `cached_channel` と `publish_snapshot` で共有 JSON を出力する。元の取得時刻を渡す。古い値の再保存で時刻を現在に更新しない。
4. パネルの「実測データの取得元」に Mac 側から見える JSON の絶対パスを設定する。
5. Wizard 等の読み値と電流符号・倍率を比較する。PC 間の時計を揃える。
6. 未取得・通信断・古いキャッシュ・トルク OFF を区別して確認し、必要な許容値を設定する。

右は実機 ID 1〜9、左は ID 11〜18。`R5` は右第5関節／ID5、`L5` は左第5関節／ID15です。UI の ID と関節番号を混同しないこと。

スナップショット時刻から2秒超過、未来時刻、無効値は有効なライブ値として表示しません。欠測をゼロ負荷と表示しません。モータートルク OFF は、それ自体をハードウェアエラーと解釈しません。

## ユーザーの確定方針

- 分離可能な実装・独立検証・別機能はサブエージェントへ並行委任する。主担当も進め、ユーザーへの応答中に作業を停止させない。同じファイルの同時編集を避ける。
- 指示された関節・区間以外の角度、基準値、速度、左右同期、動作長を勝手に変えない。
- 復元は対応する実データから行う。推定で似せたものを「復元」と呼ばない。変更前の時刻付きコピーとハッシュを残し、復元後の値／バイトを照合する。
- ShosaEdit の姿勢は基準点からの相対値、実機への書き出し時にモデルの基準値と組み合わせて絶対カウントにするという方針。実装の各経路がそれを守るか確認する。
- 動作は指定基準点から開始し、基準点で終了。ただしCSVの先頭行と、TDが現在位置からそこへ移す開始処理は別物。
- 「前の編集より絶対に負荷を増やさない」という全編集共通の制約にしない。ユーザーはこの制約による累積的な動作縮小を否定した。設定された許容値と実測・動作意図で判断する。
- 外側へ振り下ろす修正を、最初だけ外へ出して最後に急に内側へ戻す形にしない。障害物は肘付近。挙上区間では内側動作も許容される。具体的な障害物位置は未測定。
- 実機再生、FIX、LOCK、Release、トルク変更を画面確認のために自動実行しない。ユーザーが明示した対象操作の範囲を守る。
- TD の制御コードは通常変更しない。電流取り込みの組み込み時も、再生・リリース処理に無関係な変更を入れない。

## 手の向きと基準値の注意

小さいモーター2個が見える面が手のひら、その反対が手の甲。CADの見た目や過去の符号設定だけから再定義しない。身体前方とカメラ方向を混同しない。現行プレビューの身体前方は世界 +Z、上は −Y。肩から手首までの回転が積み重なるため、手の向きの問題を手首の単純反転で解決したと決めつけない。

手先位置に加えて、手の表裏・長軸、肘の位置と曲がる側、途中の回旋を両腕別々に CAD で確認する。数値検査、画面確認、実機確認を分けて報告する。元の Motion 1〜3は変更しない。

基準値はマウント姿勢や HA/HB の交換で変わってきました。親 AGENTS.md の2026-11-06基準点は当時の全軸基準です。その後の承認済み手首／指校正を、古い straight の値で上書きしてはいけません。現在のハードウェアと使用中モーションを再確認する必要があります。任意姿勢の POSITION を勝手に新基準にしないでください。
